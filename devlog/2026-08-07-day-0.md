# Day 0 — the plan before the code

No code yet. Today was about deciding what *not* to build.

The project: a ray-tracing denoiser whose convolutions contain zero multiplications — ternary weights (−1/0/+1) turn every MAC into an add, a subtract, or a skip. Target is an FPGA, using LUTs only, no DSP slices.

Decisions locked in before writing anything:

- **Simulation-first.** No FPGA board is purchased until the RTL exists, is verified bit-exact in Verilator, and synthesis reports real LUT/BRAM numbers. The board gets chosen from data, not vibes.
- **Powers-of-two requantization.** The standard BitNet requant scale is a fixed-point multiply — which would smuggle a multiplier back into the "zero multiplier" datapath. Shift + round + clamp instead. Accepted the accuracy cost on purpose.
- **Caught an overflow before writing a line of RTL:** a 16-bit accumulator overflows a 3×3 ternary conv at 32 input channels (9 · 32 · 128 = 36,864 > 32,767). Accumulators get sized per layer instead.
- **v1 is a 5-layer FCN, not a U-Net.** Residual output, G-buffer inputs. The micro U-Net waits until the boring version works.
- **One rule above all:** PyTorch, the C++ golden model, and the RTL must agree bit-for-bit against shared golden test vectors. Zero tolerance.

Next: M0, the quantization contract (`docs/QUANT_SPEC.md`) and the golden vectors everything else will be tested against.
